# ADR-0001: Schema `v1.0.0` Contract & High-Volume (20+ TB/day) Log Analytics

- **Status**: Proposed (`PR-0` pre-flight spike completed `2026-11-13`; locks `ADR-01`–`ADR-22` ahead of `PR-2`)
- **Audit Baseline**: `b08e07bde02ad9b6d7670511273e8ad0d7e9da31` (`main` / `v0.1.0`)
- **Related Issues**: `#88` (`v0alpha2` → `v1.0.0` schema contract), `#82` (20+ TB/day high-volume log analytics), `#23` (`opentelemetry-collector-contrib` component staging)
- **Live Verification Suite**: [`integration_v1_spike_live_test.go`](../../integration_v1_spike_live_test.go) (`//go:build integration`)

---

## 1. Context

Two independent engineering proposals converge on the `BQ-OTEL-Exporter` ingestion and storage boundary:

1. **Issue `#88` (`v0alpha2` → `v1.0.0`)**: Graduates the table contract from `v0alpha2` (`internal/schema/schema.go:20`) to a SemVer-frozen `v1.0.0` contract, eliminating `*_schema` sidecars and per-row `schema_version`, restructuring `payload_refs` into `ObjectRef`-compatible `object_refs`, and introducing `otel_schema_*` table-level labels.
2. **Issue `#82` (20+ TB/day Access & Edge Log Analytics)**: Targets high-volume trace-less log pipelines (`~20 TB/day` sustained), exposing gaps in per-row wire amplification, partition/clustering configurability, search index management, read-path deduplication vs. raw/rollup queries, Collector CPU efficiency, autoscaling safety, and GCS batch-load tradeoffs.
3. **Issue `#23` (Upstream `opentelemetry-collector-contrib`)**: Tracks component donation and stability promotion (`metadata.yaml:4-10`, `docs/upstream/contrib-alpha-and-releases.md`), which must remain decoupled from both table-schema freeze timing and Phase 2 operational tooling.

This ADR locks the unified architectural decisions (`ADR-01`–`ADR-22`), defines the five-layer byte accounting and timestamp contracts, specifies the `otel_schema_*` admission matrix, and records the live BigQuery, GCS, and `v0.1.0` distribution pre-flight measurements (`NV-01`–`NV-22`).

## 2. Three Decoupled Release & Versioning Tracks

1. **Track A — Table Schema Contract (`v0alpha2` → `v0alpha3` Candidate → `v1.0.0` Frozen)**:
   - Core breaking schema cuts stage first as `v0alpha3` (`otel_schema_major="0"`, `otel_schema_minor="3"`, `otel_schema_patch="0"`), preserving `TestVersionPreV1CandidateGate` (`internal/schema/schema_test.go:21-25`) until at least two independent design partners (including at least one high-volume access-log workload per `ADR-02`) complete representative workflows.
   - Because `v0alpha3` carries the final `v1.0.0` physical column set, promoting tables to `v1.0.0` requires zero row rewrites—only customer-label-preserving `bq update --set_label` or Terraform `merge(var.labels, local.otel_schema_labels)`.
2. **Track B — Go Module & Pre-Built Collector Distribution (`v0.1.0` → `v0.2.0` / `v1.0.0`)**:
   - `.goreleaser.yaml` already publishes multi-OS binary archives and OCI container manifests (`v0.1.0` tagged `2026-11-09` in `CHANGELOG.md:13`). Bundling standard OTel trimming processors (`resourceprocessor`, `attributesprocessor`, `transformprocessor`) in `example/otelcol-builder-release.yaml` belongs to Track B and requires no schema break.
3. **Track C — Collector Component Stability & Upstream `otelcol-contrib` (`#23`)**:
   - `metadata.yaml:4-10` remains authoritative (`development` → `alpha`, independent of `v1.0.0` schema freeze per `docs/upstream/contrib-alpha-and-releases.md:472`). Upstream `#23` is unblocked once the breaking schema/config cut is tagged and `contribcheck.LibraryVersion` (`internal/contribcheck/contribcheck.go:49`) is re-pinned.

## 4. Five-Layer Byte Accounting & Quota Arithmetic (`ADR-03`)

Every sizing, benchmark, and TCO table in `BQ-OTEL-Exporter` separates five distinct byte layers:

| Layer | Definition | Measured / Sizing Behavior |
| :--- | :--- | :--- |
| **1. Source Content** | Raw application log payload or OTel attribute payload before OTLP envelope framing (`-payload-bytes`). | Used only to label benchmark inputs (e.g., `1 KiB` payload); never used as a network or billing proxy. |
| **2. OTLP Wire Bytes** | Serialized `Export{Traces,Logs,Metrics}ServiceRequest` protobuf bytes arriving at the Collector OTLP receiver. | Baseline for receiver/processor sizing and OTLP-to-`ProtoRows` amplification (`1.56x` on `1 KiB` GenAI logs; `2.4x–4.2x` on synthetic trace-less access logs). |
| **3. Encoded `ProtoRows`** | Serialized row payload bytes (`otelcol_exporter_bigquery_append_bytes`) passed inside `AppendRowsRequest` (excluding gRPC transport `gzip`). | **Write API billing & throughput quota basis** (`$0.025/GiB` after `2 TiB/mo` free). Transport `gzip` (`exporter.go:529-532`) reduces network bytes only, **not** billed ingestion or throughput quota. |
| **4. BQ Logical Table Bytes** | Uncompressed columnar logical size in BigQuery (`INFORMATION_SCHEMA.TABLE_STORAGE.total_logical_bytes`). | Governs logical storage billing (`$0.020/GiB-mo` active, `$0.010/GiB-mo` long-term) and the **search-index free management cap** (`20 TB` single-region / `100 TB` `US`/`EU`). |
| **5. BQ Physical Compressed Bytes** | Capacitor + Zstandard compressed storage including 7-day time-travel + 7-day fail-safe (`active_physical_bytes`). | Governs `storage_billing_model = 'PHYSICAL'` cost (`$0.040/GiB-mo` active, `$0.020/GiB-mo` long-term); measured per workload via `NV-13`. |

### Canonical Rate & Quota Conversions

- **Decimal Daily Volume ↔ Rate**: `20 TB/day` = `20 × 10^12 B / 86,400 s` = **`231.48 MB/s` (`~231.5 MB/s`)** = `600 TB / 30-day month` (`215.6 MiB/s` binary).
- **`300 MB/s` Reference Rate**: `300 × 10^6 B/s × 86,400 s` = **`25.92 TB/day`** = `777.6 TB / 30-day month` (`750 TB/month = 25 TB/day = 289.35 MB/s`).
- **Storage Write API Throughput Quota**: **`300 MB/s` default in single regions** (`231.5 MB/s` fits within default headroom; `300 MB/s` saturates it without a quota increase) vs. **`3 GB/s` default in `US`/`EU` multi-regions** (`300 MB/s` is 10% of default). Throughput quota is scoped to the **destination BigQuery project**; connection concurrency quota is scoped to the **client credential project**.

## 5. `timestamp_source` Truth Table & Time-Column Contract (`ADR-08`, `ADR-12`)

Matches `internal/transform/rows.go:1016-1034,1055-1057` and `internal/schema/tableschema.go:274-280`. Both `time_unix_nano` and `observed_time_unix_nano` remain `REQUIRED` (`0` when unset; `observed_timestamp` is `NULL` when `ObservedTimestamp() == 0` so Unix epoch `1970-01-01` is never fabricated).

| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |

## 6. `otel_schema_*` Label Admission & Bidirectional `0.3.0` / `1.0.0` Matrix (`ADR-09`, `ADR-21`)

All four BigQuery tables carry reserved labels `otel_schema_major`, `otel_schema_minor`, `otel_schema_patch`, and `otel_schema_variant` (`"default"`). User `labels` or `<signal>.labels` entries prefixed with `otel_schema_` are rejected by `Config.Validate()` and Terraform `variables.tf`.

| Table State at Startup | Structural `CompatibilityDifferences` | `otel_schema_*` Table Labels | Exporter Behavior (`auto_create.tables = true` vs. `false`) |
| :--- | :--- | :--- | :--- |
| Table missing | N/A | Absent | Create table with current contract & labels (`auto_create.tables: true`), or fail fast (`false`). |
| `v0alpha2` layout (`schema_version` / `*_schema` / `payload_refs`) | Non-empty | Absent | **Fail startup fast** with actionable error linking [`docs/migration.md`](../migration.md). |
| Candidate `(0,3,*)` table + `0.3.0` or `1.0.0` writer | Empty | `major=0, minor=3` | **Admit** (bidirectional `0.3.0` ↔ `1.0.0` rolling-upgrade safety); `1.0.0` writer logs `WARN` with label-safe `bq update --set_label` promotion command. |
| Frozen `(1,0,*)` table + `0.3.0` or `1.0.0` writer | Empty | `major=1, minor=0` | **Admit** (bidirectional `0.3.0` ↔ `1.0.0` rolling-upgrade & rollback safety). |
| Future `1.N` table + `1.0` writer (additive `NULLABLE`/`REPEATED` cols) | Empty | `major=1, minor>=0` | **Admit** with `INFO`/`WARN` noting table minor ahead of writer. |
| Breaking `major >= 2` or structural mismatch | Non-empty or `major >= 2` | Any | **Fail startup fast** (`Start`); during mid-run schema drift, classify as retryable pause (`internal/bigquery/errors.go`) so queues retain batches without dropping rows. |
| `tables.get` `PERMISSION_DENIED` | Unverified | Unverified | Fail fast when `auto_create.tables: true`; **warn-and-defer** when `auto_create.tables: false` (write-only IAM path). |

## 7. Pre-Flight `NOT VERIFIED` Matrix (`NV-01`–`NV-22`)

Empirical results below were executed against project `haiyuan-anarres-dev-806843` (`US`, `2026-11-13`) via [`integration_v1_spike_live_test.go`](../../integration_v1_spike_live_test.go) and the `v0.1.0` release artifacts (`NV-21`).

| ID | Item | Status | Empirical Finding & Operational Consequence |
| :--- | :--- | :--- | :--- |
| **`NV-01`** | `OBJ.FETCH_METADATA` & `OBJ.GET_ACCESS_URL` with `details` & `details.otel` | **VERIFIED (Live BQ+GCS)** | `OBJ.MAKE_REF`, `details: {}`, and `details: {"gcs_metadata":{"content_type":"text/plain"}}` (with `NULL` or pinned generation) all succeeded and produced working `HTTP 200` signed URLs via `OBJ.GET_ACCESS_URL(ref, 'r')`. **Critical discovery**: both `case_d` (`gcs_metadata` + `otel`) and `case_e` (`otel` only) **failed inside `OBJ.FETCH_METADATA`** with `{"errors":[{"code":400,"message":"Invalid field in objectref details, only a JSON object named gcs_metadata or errors is allowed","source":"OBJ.FETCH_METADATA"}]}` and caused `OBJ.GET_ACCESS_URL` to return `read_url = NULL`. **`ADR-11` locks `details` strictly to `"gcs_metadata"` (`content_type`, `size`, and `md5_hash`/`updated` only when verified).** |
| **`NV-02`** | `otel_logs_dedup` partition pruning & slot cost (`QUALIFY insert_id IS NULL OR ...` vs. `UNION ALL`) | **VERIFIED (Live BQ)** | On a 3-partition `require_partition_filter = true` table (`20` `NULL` `insert_id` + `10` deduped non-null rows/day): **both** `QUALIFY insert_id IS NULL OR ROW_NUMBER() ... = 1` and two-branch `UNION ALL` achieved **exact single-partition pruning** (`1`-day dry-run & execution scanned `1` partition / `2,272 B` vs. `3` partitions / `6,816 B` for 3 days) and identical `30`-row output (`1,537 ms` vs. `1,403 ms` slots on 1-day; `1,499 ms` vs. `1,237 ms` on 3-day). **Use `QUALIFY insert_id IS NULL OR ROW_NUMBER() ... = 1` (`PR-4`)** to preserve single-scan view DDL while pruning partitions. |
| **`NV-03`** | Managed Iceberg tables & `STRING` JSON subscripting | **Deferred (`ADR-05`)** | Held out of `v1.0.0` freeze; requires a dedicated post-`1.0` BigLake RFC. |
| **`NV-04`** | `TO_JSON_STRING` byte identity vs. exporter proto3 JSON | **VERIFIED (Live BQ)** | `TO_JSON_STRING` sorts object keys lexicographically (`{"a":"<tag>&val","i64_max":...,"z":1}`), omits whitespace around `:` and `,`, and **does not** HTML-escape `<`, `>`, or `&`.
