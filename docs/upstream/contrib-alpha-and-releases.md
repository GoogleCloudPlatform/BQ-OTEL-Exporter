The BigQuery exporter writes OTLP traces, logs, and metrics to BigQuery tables
through the [BigQuery Storage Write API](https://cloud.google.com/bigquery/docs/write-api).
Each signal goes to its own table with a documented, versioned schema, so the
data can be queried with SQL without a Cloud Logging sink, a Pub/Sub and
Dataflow pipeline, or batch file loads in between.

This component wraps the
[github.com/GoogleCloudPlatform/BQ-OTEL-Exporter](https://github.com/GoogleCloudPlatform/BQ-OTEL-Exporter)
library, which holds the implementation, the table schema contract, and their
tests. The configuration is the library's configuration.

The component is part of the `otelcol-contrib` distribution. This
configuration receives OTLP and writes all three signals to BigQuery:

```yaml
receivers:
  otlp:
    protocols:
      grpc:
      http:

exporters:
  bigquery:
    project: my-project
    dataset: otel

service:
  pipelines:
    traces:
      receivers: [otlp]
      exporters: [bigquery]
    logs:
      receivers: [otlp]
      exporters: [bigquery]
    metrics:
      receivers: [otlp]
      exporters: [bigquery]
```

## Configuration

`project` and `dataset` are required; there is no default destination.

```yaml
exporters:
  bigquery:
    project: my-project
    dataset: otel
```

Each signal has its own table. The names default to `otel_spans`, `otel_logs`,
and `otel_metrics`:

```yaml
exporters:
  bigquery:
    project: my-project
    dataset: otel
    traces:
      table: otel_spans
    logs:
      table: otel_logs
    metrics:
      table: otel_metrics
```

The exporter also accepts the standard `timeout`, `sending_queue`, and
`retry_on_failure` settings. The sending queue defaults to 8 consumers, the
in-flight request window of the Storage Write API client, with batching off.

To keep queued telemetry across collector restarts, back the sending queue
with a storage extension such as `file_storage`. The relevant parts of the
configuration are:

```yaml
extensions:
  file_storage:
    directory: /var/lib/otelcol/file_storage

exporters:
  bigquery:
    project: my-project
    dataset: otel
    sending_queue:
      enabled: true
      storage: file_storage

service:
  extensions: [file_storage]
```

The full option reference covers credentials, dataset and table creation,
write tuning, structural limits, quarantine, payload offload to Cloud Storage,
and redaction. It is in the
[library README](https://github.com/GoogleCloudPlatform/BQ-OTEL-Exporter/blob/v0.1.0/README.md#configuration).

## Delivery semantics

Delivery is at least once. The exporter appends to the Storage Write API
default stream, so a retried append can store the same record twice. The
library documents the read-time deduplication views for that case.

distribution must be in the builder config and in the respective testing
harnesses, and that a component which cannot be tested within that framework
must increase the non-testable components number, with a comment in the pull

destination, [contrib-testbed-staging.md](contrib-testbed-staging.md) implements

`testbed/datareceivers/bigquerydatareceiver/` (configured with

`auto_create.dataset: false` / `auto_create.tables: false` so REST metadata
calls are skipped). Therefore, PR 3 takes the **testbed harness route**: wire
`exporter/bigqueryexporter` into `cmd/oteltestbedcol/builder-config.yaml` (via
`make genoteltestbedcol` / `make oteltestbedcol`) and run the standard testbed
